# 0004. `values.schema.json` is output, not inference evidence

Status: Accepted
Date: 2026-06-19 (CLAUDE.md "`values.schema.json` is output, not inference evidence", commit ba34b74d)

## Context

helm-schema produces a `values.schema.json`-shaped artifact. Charts and their
dependencies sometimes ship their own `values.schema.json`. Such a file is an
external author assertion: it may be stale, incomplete, hand-written for
another purpose, or generated by another tool.

## Decision

helm-schema never automatically reads an existing chart or dependency
`values.schema.json` as input evidence. The accepted input schema is
recovered only from what the chart does: templates and helper bodies,
structural control flow over `.Values`, composed `values.yaml` defaults and
user-supplied values files, comments as metadata only (ADR [0005](0005-values-comments-are-description-metadata-only.md)), and
resource schemas for rendered Kubernetes/CRD sinks.

## Consequences

- Shipped schemas are not ingested, not intersected with the output, and not
  used to infer types, shapes, nullability, requiredness or guards.
- User-provided override schemas remain allowed, but only as explicit
  caller policy inputs, never as discovered chart facts.
- The correctness contract defines the accepted set without them
  (`plan/from-scratch-architecture.md` §2, ADR [0002](0002-soundness-never-reject-a-working-configuration.md)).
- Helm oracle runs remove shipped schemas from private chart copies so they
  do not influence adjudication (`plan/schema-bug-hunt-v1-progress.md`
  "Decision register", Helm bullet).
